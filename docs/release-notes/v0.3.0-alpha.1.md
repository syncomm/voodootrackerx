# VoodooTracker X v0.3.0-alpha.1 Release Notes

Release target: `v0.3.0-alpha.1`

Theme: From-Scratch Composition Alpha.

## Overview

VoodooTracker X `v0.3.0-alpha.1` is the From-Scratch Composition
Alpha: create instruments, generate or import samples, map multisample note
ranges, compose patterns and orders, export XM, reopen the result, and render
WAV/M4A audio.

The final composition/XM round-trip gate concluded **CONDITIONAL GO** with no
known product blocker. This remains alpha-quality software and the supported
round trip is intentionally limited to the current VTX editable XM subset.

## Highlights

- Start an editable song with `File > New` and add instruments with
  `Edit > New Instrument`.
- Generate deterministic SINE sample data or import WAV, AIFF/AIFC, and the
  supported native-FLAC subset.
- Append multiple represented samples to an instrument with
  `Add as New Sample`.
- Assign inclusive note ranges through the explicit manual `MAP RANGE…`
  workflow over the exact 96-note XM keymap.
- Audition instruments through their note maps and audition the selected
  sample directly in the Sample Editor.
- Enter pattern data, create and assign patterns, and arrange song/order data.
- Export the supported editable state as XM, reopen it read-only, and make a
  new editable copy when supported.
- Render the complete song as 48 kHz Float32 WAV or AAC-in-M4A.

## From-Scratch Composition

The supported release flow is:

```text
File > New
-> create instruments
-> generate/import samples
-> append multiple samples
-> map sample note ranges manually
-> audition instruments and samples
-> enter patterns
-> arrange song/order data
-> play
-> Export XM
-> reopen
-> Export WAV/M4A
```

File New provides an unnamed I01 with an honest empty S01 destination. New
Instrument appends and selects another empty instrument through one undoable
edit. Pattern Bank, Pattern Ops, Order Ops, normal Play/Stop, Play Current
Pattern, and Loop-at-Play-start provide the current small-song composition
workflow.

## Instrument & Sample Workflow

- SINE creates deterministic looped mono 16-bit PCM and maps the first sample
  across all notes.
- LOAD accepts WAV/WAVE, AIFF/AIF, AIFC, and native `fLaC` containers.
- Native FLAC import is limited to preflighted 16-bit or 24-bit mono/stereo
  sources. Stereo imports offer Mix to Mono, Left, or Right.
- Every supported import becomes the same canonical document-owned mono
  16-bit XM sample representation.
- Imported sample names derive from the source filename stem and fit the XM
  sample-name field.
- The document owns the decoded PCM. Playback, undo/redo, Export XM, and audio
  export do not depend on the original source file after import.
- Occupied LOAD offers Replace Current Sample, Add as New Sample, or Cancel.
  Add is append-only, selects the new S02+ slot, and does not change existing
  keymap assignments.

## Keymap & Audition Correctness

The document retains the canonical 96-note XM C-0...B-7 keymap. `MAP RANGE…`
assigns the selected represented sample to an explicit inclusive From/To range
through one undoable edit. Mapping C-5...B-5 changes exactly indices 60...71;
B-4 remains on S01 and C-6 returns to S01.

Instrument Editor computer/on-screen audition, pattern-entry audition, and
editable playback resolve the played note through the instrument keymap.
Changing the selected sample does not change that routing: selected sample is
editing focus only. Sample Editor AUDITION intentionally plays the selected
sample directly without consulting the keymap.

The committed-ownership strip displays exactly the same movable 36-note range
and horizontal note boundaries as the audition piano. It remains read-only;
graphical range selection and drag-to-paint mapping are deferred.

## XM Export / Round Trip

`File > Export XM...` writes stopped editable documents to a user-selected
destination using the current VTX editable subset. The exported XM reopens
through the normal loaded/read-only path with supported instruments, samples,
keymaps, patterns, orders, loops, envelopes, tuning, panning, and volume
preserved.

Supported stopped Linear-table XM files may transition to a new untitled
in-memory document through `File > Make Editable Copy`. Amiga-frequency-table
XM files are refused because the editable model is Linear-only; VTX does not
silently convert them. This release does not claim arbitrary-XM byte parity or
full FastTracker II, OpenMPT, or MilkyTracker parity.

## Rendered Audio Export

- `File > Export Audio > WAV...` produces whole-song 48 kHz Float32 WAV with
  the VTX product render profile, a 3-second tail, export-boundary
  auto-headroom, progress, and cooperative cancellation.
- `File > Export Audio > M4A...` reuses the completed scaled Float32 render and
  encodes fixed 192 kbps AAC for convenient sharing.
- Both formats write only to the selected destination, remove temporary output
  on cancellation or failure, and do not mutate the document or claim its
  source path.

## Reliability & Test Coverage

The final gate added a deterministic integration test that begins with the
default editable document, creates distinct samples and two instruments, maps
C-5...B-5, arranges two patterns in two orders, verifies resolved sample
identities, exports deterministic XM bytes, and semantically reopens the file.

Final-gate verification passed 117 renderer tests, 24 parser tests, 141 full
SwiftPM tests, 1,412 macOS Xcode tests, and 222 Python tests with zero failures.
Five synthetic XM fixtures regenerated byte-identically, and repository
hygiene/private-artifact scans passed.

The generated-data Debug-app workflow also passed through composition,
playback, XM reopen/editable-copy, WAV/M4A export, editor lifecycle, and tracker
viewport wrap/alignment. The gate did not claim an AirPods hardware smoke
because both paired devices were unavailable.

## Known Alpha Limitations

- Save and Save As remain disabled. Export XM is the current persistence path.
- Loaded modules remain read-only. `File > Make Editable Copy` is the explicit
  supported transition, and it refuses Amiga-frequency-table or otherwise
  non-representable XM state.
- Export XM covers only the current VTX editable subset; arbitrary-XM round
  trip and full tracker parity are not claimed.
- Graphical keymap selection, drag-to-paint, and automatic assignment are
  deferred; use the manual inclusive `MAP RANGE…` sheet.
- Sample delete, clear, reorder, move/swap, and duplicate remain deferred.
  Add as New Sample is append-only.
- XI Import/Export is not part of this release.
- Native FLAC support is not universal. Valid 8-bit FLAC is unsupported by the
  selected Apple decoder, untested depths are rejected, and Ogg-FLAC is not
  supported.
- AIFF/AIFC metadata, markers, and loop import remain deferred.
- FLAC tags, pictures, cues, seek tables, application blocks, ReplayGain,
  embedded names, and loop-like metadata are ignored.
- Advanced sample loop, PCM, waveform-editing, processing, and additional
  generator controls remain unavailable.
- MIDI input is not part of this release. Broader UI polish remains deferred.
- AUv3 remains a post-v1.0 direction and is not included in this alpha.
- The final gate did not claim AirPods verification. An optional maintainer
  smoke may be performed when hardware is available; hardware unavailability
  alone does not block release absent a new defect.

separate app marketing-version field, and this release-preparation PR does not
add one. Do not create or push the tag from this PR. After this PR merges and
the maintainer completes the final smoke, run:
