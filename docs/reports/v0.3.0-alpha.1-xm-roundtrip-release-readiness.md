# v0.3.0-alpha.1 XM Round-Trip Release Readiness

Date: 2026-08-11

Audited base: `main` at `05ee3e7`; final-gate branch:
`release/v0.3.0-alpha.1-final-gate`.

Scope: the represented from-scratch composition subset, not arbitrary-XM byte parity.

## Result

The prior release blockers are resolved on `main`. PR #370 routed Instrument
Editor audition, pattern-entry audition, and editable playback through one
instrument-plus-note keymap resolver. PR #371 removed graphical hit/drag mapping
and transient selection state while retaining the explicit manual `MAP RANGE…`
sheet. PR #372 projected committed ownership through the audition piano's exact
visible range and shared key-boundary geometry.

The final rerun confirms C-5/index 60 through B-5/index 71 maps exactly 12 notes
to S02, while B-4/index 59 and C-6/index 72 stay on S01. Selection changes do
not affect routing, Sample Editor audition remains direct-selected-sample, and
editable/read-only ownership projections agree. `Edit > New Instrument`
appends and selects empty I02/S01 through one undoable edit, and redo restores
it.

A new integration test starts from the default editable document, creates two
distinct samples and two instruments, applies the exact map, arranges two
patterns in two orders, resolves both sample identities through the full plan,
and proves deterministic XM export/reopen semantics before WAV/M4A export. The
same workflow passed through the Debug app, including Make Editable Copy,
focus/close behavior, and tracker wrap geometry. No production code or file
format changed.

The paired AirPods devices were disconnected and not reachable during this run,
so the hardware idle/quick-audition smoke is explicitly unclaimed. There is no
known product blocker; release preparation remains conditioned only on that
maintainer hardware confirmation and the documented alpha limitations below.

Legend: **E** represented/editable, **P** represented/preserved read-only,
**C** intentional canonical/default output, **D** unsupported/deferred,
**R** open non-blocking risk, **B** release blocker. No known code workflow is
classed **B** on this branch.

## Audit defects and blockers

1. Make Editable Copy accepted Amiga-table XM while the editable model/export is
   Linear. It now rejects that source rather than reporting a lossy success.
2. Writer channel dimensions, non-finite PCM, sparse represented sample order,
   and unmappable note-map entries could be silently canonicalized. They now
   return typed writer failures before any destination write.
3. Tests now pin preservation of an existing destination on validation failure
   and replacement/reopen through the atomic success path.
4. The original audit proved live editable audition/playback did not reliably honor
   the represented keymap. The dedicated correction removes selected-sample routing
   from instrument-note requests and resolves live triggers through the map.
5. The full 96-note summary and movable three-octave piano presented incompatible
   horizontal scales. PR #371 removed summary hit/drag selection, transient overlay/
   readout/accessibility state, and sheet prefill while preserving committed ownership
   and the manual inclusive range operation. This branch now displays only the piano's
   exact visible 36-note ownership slice and derives segment boundaries from the same
   keyboard layout geometry.

Valid supported-document bytes are unchanged; no on-disk format was introduced.

## Atomicity and failure revalidation

Invalid editable invariants still fail before destination replacement. Writer
failure and cancellation preserve an existing final file, remove temporary
output, and report failure truthfully; successful replacement remains atomic.
The final file/private-data scans found no local input or artifact leak.
