# v0.3.0-alpha.1 XM Round-Trip Release Readiness

Date: 2026-08-07

Audited base: `main` at `00dd08f`; visible-ownership alignment is on the current
feature branch.

Scope: the represented from-scratch composition subset, not arbitrary-XM byte parity.

## Result

The dedicated keymap-resolution correction merged in PR #370. Instrument Editor
and pattern audition plus editable live/adapter scheduling now use one exact
note-map resolver; deterministic distinct-S01/S02 coverage proves selection
independence, direct Sample Editor audition, and map undo/redo.

The release UX review then exposed a separate blocker: the fixed full 96-note
C-0...B-7 ownership summary and movable three-octave audition piano shared a
width but not a scale. The graphical-selection deferral merged in PR #371:
ownership remains noninteractive, graphical hit/drag selection and prefill are
removed, and the explicit manual `MAP RANGE…` selectors remain authoritative.

This branch completes the visual correction by projecting the canonical map
onto exactly the piano's current 36-note range through shared note-boundary
geometry. A visible C-4...B-6 piano therefore displays only C-4...B-6
ownership. Mapping indices 60...71 assigns C-5...B-5 to S02; B-4/index 59 and
C-6/index 72 remain S01, and the S02 segment ends at the same boundary where
the piano's C-6 key begins. Octave navigation rebuilds the strip and piano from
one visible-range state without document history. The projection is identical
for editable and loaded read-only documents and does not depend on selected-
sample editing focus; read-only `MAP RANGE…` gating is unchanged.

The canonical 96-entry document map, manual inclusive range sheet, coordinator,
undo/redo, note resolution, audition, playback, parser/writer, and export
semantics are unchanged. Release disposition remains NO-GO until the visible-
ownership alignment lands and the final automated/manual release gate,
including `Edit > New Instrument`, is rerun.

Legend: **E** represented/editable, **P** represented/preserved read-only,
**C** intentional canonical/default output, **D** unsupported/deferred,
**R** open non-blocking risk, **B** release blocker. No known code workflow
remains classed **B** on this branch; release process remains gated as above.

## Audit defects and blockers

1. Make Editable Copy accepted Amiga-table XM while the editable model/export is
   Linear. It now rejects that source rather than reporting a lossy success.
2. Writer channel dimensions, non-finite PCM, sparse represented sample order,
   and unmappable note-map entries could be silently canonicalized. They now
   return typed writer failures before any destination write.
3. Tests now pin preservation of an existing destination on validation failure
   and replacement/reopen through the atomic success path.
4. The original audit proved live editable audition/playback did not reliably honor
   the represented keymap. The dedicated correction removes selected-sample routing
   from instrument-note requests and resolves live triggers through the map.
5. The full 96-note summary and movable three-octave piano presented incompatible
   horizontal scales. PR #371 removed summary hit/drag selection, transient overlay/
   readout/accessibility state, and sheet prefill while preserving committed ownership
   and the manual inclusive range operation. This branch now displays only the piano's
   exact visible 36-note ownership slice and derives segment boundaries from the same
   keyboard layout geometry.

Valid supported-document bytes are unchanged; no on-disk format was introduced.
