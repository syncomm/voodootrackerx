# Synthetic XM Reference Fixture Pack

This directory is the public-safe home for future deterministic XM reference
fixtures. It starts with generator source and manifest contracts only; binary
XM files and reference renders are intentionally deferred until explicit
reviewed fixture PRs.

## Purpose

The pack will provide small redistributable XM modules for parser, editor,
instrument/sample, preview-availability, and later audio-comparison tests.
Existing `tests/fixtures/minimal.xm` remains a tiny parser smoke fixture, but it
does not contain meaningful instrument/sample payload for positive editor
preview or audition planning tests.

## Provenance And License Rules

- Fixtures must be generated by this repository's tooling or hand-authored by
  the maintainer for VoodooTracker X.
- Fixture source, manifests, and approved binary fixtures inherit the
  repository license unless a future design note states otherwise.
- Do not use private XM modules, copied tracker modules, commercial sample
  material, copyrighted songs, private corpus maps, private filenames, or
  private corpus-derived patterns, samples, instruments, names, or effects.
- Automated tests must use committed public fixtures or synthetic data created
  inside the test. They must not require private modules or local paths.

## Expected Layout

The intended fixture-pack layout is:

```text
tests/reference-xm/
  README.md
  source/
  generated/
  reference-renders/
```

`source/` stores reviewed source manifests or future generator inputs.
`generated/` is reserved for approved binary XM fixtures. `reference-renders/`
is reserved for optional approved reference assets or compact metrics. Empty
directories are not tracked unless a future repo convention adds placeholders.

## Generator Workflow

Use the deterministic skeleton from the repo root:

```bash
python3 scripts/generate-synthetic-xm-fixtures.py
python3 scripts/generate-synthetic-xm-fixtures.py --print-paths
python3 scripts/generate-synthetic-xm-fixtures.py --write-manifest
```

The default command prints the manifest to stdout and writes no files.
`--write-manifest` writes only
`tests/reference-xm/source/basic-instrument-sample.manifest.json`. It does not
emit XM bytes, WAV renders, JSON reports, Markdown reports, traces, screenshots,
or logs.

Generated WAV, JSON, Markdown, trace, log, screenshot, and exploratory render
artifacts stay under `/tmp` or another ignored local path unless a future PR
explicitly approves committing that exact artifact.

## Planned Fixtures

The first planned fixture is `basic-instrument-sample.xm`: one instrument, one
deterministic synthetic sample, simple note events, and real sample payload for
parser/editor positive-path tests.

Binary XM fixture commits must be explicit, small, deterministic, and reviewed
as test asset changes. No binary XM fixture is committed by this skeleton PR.
